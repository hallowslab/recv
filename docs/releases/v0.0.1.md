First release of `recv`.

`recv` is an HTTP upload server with QR pairing, and the library behind
ExifFlow's browser-upload feature. It is a sibling of `rftps`: same upload root,
same event stream, same durable record store.

### Highlights

- **Browser upload** - multi-file, drag & drop, phone camera/gallery, per-file
  and overall progress.
- **QR pairing** - the QR carries the URL with the token in the `#fragment`, so
  the server never sees it. The page exchanges the token for an `HttpOnly`
  session cookie.
- **Optional password** - `--require-password` also demands the username/password
  on pairing.
- **Replication parity** - `--record-store` writes the same `pending` records as
  `rftps`, so `replicator-rs` replays HTTP uploads exactly like FTP uploads.
- **Optional HTTPS** - plain HTTP by default (phone-friendly); `--enable-https`
  serves TLS, with `include-pem-files` for embedded certificates.

### Notes

- HTTP defaults to port `41213`.
- CLI flags: `--address`, `--port`, `--directory`, `--username`, `--password`,
  `--require-password`, `--enable-https`, `--cert-pem`, `--key-pem`,
  `--external-host`, `--record-store`, `--token`, `--no-qr`, `--max-upload-size`.
